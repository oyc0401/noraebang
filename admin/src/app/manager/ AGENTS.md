# 어드민 사이트 규칙


# 관리자페이지 설명
총 왼쪽섹션 / 가운데 섹션 / 오른쪽 섹션으로 구성되어있는 관리자페이지이다.




### 아티스트 리스트 컴포넌트
해당 섹션은 왼쪽 섹션이고, 기본적으로 페이지네이션이 1000단위로 불러오는 무한스크롤이다.

아티스트카드에는 해당 아티스트의 defalut썸네일, name, nameKo, nameJa가 보여진다.
이때 `${name} (${nameKo})` 이런 형식으로 괄호안에 표시한다.
nameJa, nameLatin도 작게 보여준다.

분류(catalog도 보여준다.)
artistId도 보여진다. 스포티파이 인기도도 보여진다. 몇곡 있는지도 보여진다. 

해당 섹션 내에는 정렬 드롭다운 버튼이 있다. (디폴트: ID순만 있지만, 나중에 더 추가할 수 있도록 확장 가능성 열어두기. 나중에는 아티스트의 스포티파이곡의 그룹이 많은 순 이런 복잡한 정렬도 추가할 예정.)

필터 기능도 있다. 그 필터를 누르면 다이얼로그가 뜨면서, 다중선택이 가능한 옵션이 뜬다. ex)곡이 있는곡만 표시 / 없는곡만 표시 / 분류가 JPOP인 곡만 보기 / 분류가 없는 곡만 보기 등등 추가할 예정이므로 이것도 확장 가능성이 크도록 파일을 따로 분리한다.

그리고 검색창도 있다.
해당 검색창에 검색을 하면 그 검색창 안에 적힌 내용이 들어있는 아티스트만 조회한다. include ("탄소년" 입력시 방탄소년단 이 포함되어 검색됌.)
검색창에 숫자를 입력하면 artistID검색으로 취급한다.

아티스트를 클릭하면 http://localhost:3002/artists#1 처럼 해쉬가 생긴다.
해당 해쉬가 선택된 상태로 해당 페이지에 접속하면 해당 아티스트가 선택된채로 접속이 되며, 무한스크롤도 해당 아티스트를 보여준다. (페이지가 500단위로 불러오지만, 해시가 #2600이라면, 2500~3000을 불러와준다. 그리고 더 아래로 내리면 2500~3500이 불러와지는 형식임. )
그리고 위 방향키, 아래 방향키를 누르면 선택된 아티스트를 이동할 수 있다.
(페이지네이션이 1~500까지 불러왔지만 지금 선택된 아티스트가 500이고, 아래키를 누르면 무한스크롤이 적용되어서 501번을 불러온다.)


### 중앙 섹션
중앙에는 선택된 아티스트의 정보들, 스포티파이 정보들이 상단에 보여지고

하단에는 해당 아티스트의 모든 Song들이 보여진다.



### 아티스트 스포티파이 트랙 리스트 컴포넌트
해당 아티스트가 가지고 있는 모든 스포티파이 트랙을 보여준다.

중앙섹션에서 해당 아티스트를 편집할 수 있다.
이름/nameKo등등 편집, 썸네일 편집, slug편집, 분류 편집, 스포티파이 아티스트 정보 / 아티스트 삭제 / 아티스트 병합(해당 아티스트를 다른 아티스트에게 병합하는건데, 현재 아티스트의 모든 곡을 해당 아티스트에게 이전하고, 현재 아티스트는 삭제하는 기능) /스포티파이 id편집(삭제도 가능)/ 스포티파이 바로가기 / 유튜브 바로가기 를 가능하게 해야해. 


아래에 있는 곡 리스트에는 곡 카드에 곡 이름 / 곡Id, TJId, TjSong의 name, TjSong의 원본 artist, 현재 곡을 같이 소유하는 아티스트의 이름(Id), 해당 곡이 연결된 스포티파이그룹의 정보 / primary트랙의 정보 / 그룹상세보기 다이얼로그 여는 버튼 이 있어야해.

### 오른쪽 스포티파이곡 섹션
오른쪽 섹션은 기본적으로 스포티파이 그룹의 primary트랙들을 보여주는데, 만약에 그룹에 속하지 않은 spotifyTrack이 있으면 맨 아래쪽에 spotifyTrack들을 보여준다,
스포티파이트랙 카드에는 곡이름, 트랙Id, 스포티파이 썸네일, 곡등록날짜, 곡 길이, 인기도, 포함된그룹Id, 그룹상세보기 다이얼로그 열기, 스포티파이 곡 열기 가 있어.

### 폴더 규칙
폴더 안에는 page.tsx, action.ts가 존재한다.

### /app에서는 다른 폴더를 의존하지 않는다.

어드민 페이지는 금방 생기고 금방 사라지고 요구사항이 무궁무진하게 생기기때문에 다른 코드를 의존하지 않게 함으로써 변경이 쉽게 한다.

/lib, /service 폴더는 의존 가능하고 깔끔하게 관리하자. 재사용율 100%임.

### 서버액션 사용
action.ts에서는 prisma를 사용하는 서버액션 함수들이다.

/manager 페이지는 복잡하기 때문에, zustand, customhook을 활용할 수 있다.

store는 다른 컴포넌트끼리 꼭 공유해야하는 정보만 저장한다.
(현재 선택된 아티스트 ID, 다이얼로그 열림 여부 등등.)
artist배열, Song배열과 같은건 store에 두지 않고, useMemo등을 사용한 커스텀 훅에 저장한다.



왼쪽섹션이 선택된 artistId를 바꿈 -> 선택된 artistId가 바뀜 -> 가운데섹션이 artistId를 참조했는데, 바뀌었으니 커스텀훅에서 데이터를 다시 가져옴. 의 플로우로 구성.
