# 노래방 번호 찾기

일본어 곡을 노래방에서 부르고 싶을 때, 곡 제목이나 아티스트 이름만으로 TJ/금영 번호를 빠르게 찾을 수 있도록 만든 검색 서비스입니다. YouTube Music, Spotify 링크를 붙여넣어도 해당 곡의 노래방 등록 여부를 확인할 수 있고, 원하는 곡이 없으면 TJ 노래 신청 흐름까지 이어집니다.

이 프로젝트는 단순 검색 화면만이 아니라, 외부 음악 데이터와 노래방 데이터를 연결하고 운영자가 데이터 품질을 관리할 수 있는 어드민 콘솔까지 포함한 풀스택 프로젝트입니다.

## 문제 정의

일본어 곡은 한국어 표기, 원문 표기, 로마자 표기, 발음 표기가 섞여 검색되는 경우가 많습니다. 또한 같은 곡이 YouTube, Spotify, TJ 노래방 데이터에서 서로 다른 제목과 아티스트 이름으로 제공되기 때문에 단순 문자열 검색만으로는 원하는 결과를 찾기 어렵습니다.

이 프로젝트는 다음 문제를 해결하는 것을 목표로 했습니다.

- 사용자가 기억하는 표기 방식과 실제 데이터 표기가 달라도 곡을 찾을 수 있게 하기
- YouTube Music/Spotify 링크에서 시작한 탐색을 노래방 번호 검색으로 연결하기
- Spotify, YouTube, TJ 신청곡 등 여러 출처의 데이터를 하나의 곡/아티스트 데이터로 정리하기
- 운영자가 잘못 연결된 데이터, 미연결 트랙, 사용자 신고를 빠르게 확인하고 수정할 수 있게 하기
- 검색 기록과 클릭 데이터를 기반으로 검색 품질 개선 지점을 찾기

## 주요 기능

### 사용자 웹앱

- 곡 제목, 아티스트 이름 기반 통합 검색
- 검색 자동완성 및 최근 검색어 관리
- YouTube Music/Spotify 링크 붙여넣기 검색
- 곡 상세 페이지에서 노래방 번호, 아티스트, Spotify/YouTube 정보 확인
- 원하는 곡이 없을 때 TJ 노래 신청 페이지로 이동
- 잘못된 곡/아티스트 정보 신고

### 운영 어드민

- 아티스트, 곡, 노래방 번호, Spotify 트랙, YouTube 비디오 데이터 관리
- 좌측 목록, 중앙 상세, 우측 외부 데이터 패널로 구성된 3패널 운영 콘솔
- Spotify/YouTube/TJ 신청곡의 연결/미연결 상태 확인
- 아티스트 이름, 별칭, 병합, 삭제 등 데이터 정정 작업
- 사용자 신고 상태 관리 및 운영 메모 작성
- 검색 기록, 클릭 로그, 전환율, 인기 검색어/곡/아티스트 통계 확인

### 검색 및 데이터 파이프라인

- Typesense 기반 아티스트/곡 통합 검색
- 한국어, 일본어, 로마자, 발음, 공백 제거 버전 등 다중 검색 필드 구성
- 검색 엔진 결과 순서를 유지한 DB 상세 데이터 조합
- Swagger 스키마 기반 Orval API 클라이언트 코드 생성
- 검색 기록과 클릭 로그 저장
- 내부 API를 통한 Typesense 인덱스 재생성
- Spotify/YouTube/TJ 데이터를 수집하고 곡 데이터와 매칭하는 관리 스크립트

## 기술적으로 신경 쓴 부분

### 1. 다국어 검색 품질

일본어 곡 검색은 표기 변형이 많기 때문에 단일 title 필드 검색만으로는 부족했습니다. Typesense 인덱스에 한국어/일본어/로마자/발음/정규화 필드를 나누고, 공백과 특수문자 차이를 흡수하는 전처리 로직을 추가했습니다.

### 2. 운영 가능한 데이터 구조

곡, 아티스트, 노래방 번호, Spotify 트랙, YouTube 비디오, TJ 신청곡을 별도 엔티티로 분리하고 관계 테이블로 연결했습니다. 덕분에 외부 데이터가 잘못 매칭되었을 때 운영 콘솔에서 연결 상태를 확인하고 수정할 수 있습니다.

### 3. 타입 안전한 API 계약

NestJS Swagger 문서를 기반으로 Orval이 React Query 훅과 DTO 타입을 생성합니다. 프론트엔드는 생성된 API 클라이언트를 사용하고, 공통 fetch 계층에서 인증 토큰 갱신과 에러 처리를 담당합니다.

### 4. 운영자 워크플로우 중심 UI

어드민은 단순 테이블 CRUD가 아니라 운영자가 실제로 데이터 품질을 검수하는 흐름에 맞춰 구성했습니다. 아티스트를 선택하면 중앙에서 상세 정보를 보고, 오른쪽 패널에서 Spotify, YouTube, TJ 신청곡 연결 상태를 전환하며 확인할 수 있습니다.

### 5. 테스트 가능한 매칭 로직

외부 음악 데이터 매칭은 오탐 위험이 높기 때문에 제목 정규화, 중복 트랙 판별, Spotify 후보 매칭 같은 순수 로직을 테스트로 고정했습니다. 완전 일치, 공백 차이, 괄호/버전 표기, feat/with, 실제 실패 케이스를 테스트에 포함했습니다.


## 테스트

주요 테스트 대상은 검색과 데이터 매칭 품질에 직접 영향을 주는 순수 로직입니다.

- 검색어 정규화
- Typesense 인덱스용 텍스트 전처리
- 아티스트 파서
- Spotify 트랙 매칭
- 중복/버전 트랙 판별
- 일본어/로마자 발음 변환

```bash
# 백엔드 테스트
pnpm --filter backend test

# 어드민 로직 테스트
pnpm --filter admin test
```

## 설치 및 실행

```bash
# 의존성 설치
pnpm install

# Prisma 클라이언트 생성
pnpm generate

# 개발 서버 실행 (백엔드 + 프론트엔드 + 어드민)
pnpm dev
```

## 향후 계획

1. 전체 곡 커버리지 확대: 더 많은 곡을 YouTube Music/Spotify 링크로 검색할 수 있도록 데이터 확장
2. 운영 콘솔 고도화: 미연결 데이터 추천, 대량 승인/보류, 검색 품질 이슈 큐 추가
3. 플레이리스트 지원: 애니메이션, 아티스트, 장르별 노래방 곡 모음 제공
4. 개인화 추천: 사용자 검색/클릭 기반 추천곡 제공
